# ServiceFlow

**Дополнительные работы автосервиса: предложение → решение клиента → разрешённый ремонт.**

Работающий модуль заказ-наряда на **Next.js + Chakra UI + FastAPI**. Монорепозиторий, светлая и тёмная темы, адаптивный интерфейс, SQLite и демонстрационные данные. Можно запустить без регистрации, API-ключей и внешних сервисов.

**[Полный разбор тестового задания → docs/solution.md](docs/solution.md)**: вопросы заказчику, предположения, процесс, права, статусы, исключения, критерии приёмки, данные, интерфейс и работа с ИИ.

## Быстрый запуск

### Вариант 1 — Docker

Нужен работающий Docker Desktop / Docker Engine с Compose v2.

```bash
git clone https://github.com/djimbik/car_repair_shop.git
cd car_repair_shop
docker compose up --build
```

Откройте **http://localhost:3000**. Swagger: **http://localhost:8000/docs**.

Первая сборка скачивает зависимости. Последующие запуски: `docker compose up`. База хранится в именованном volume `serviceflow-data`. Остановка: `Ctrl+C`, затем `docker compose down`. Данные сохранятся.

### Вариант 2 — без Docker, одной командой

Нужны **Python 3.11+**, **Node.js 22+** с npm и доступ в интернет для первой установки зависимостей. Рекомендуется Node.js 24 LTS. Git необязателен: можно скачать ZIP репозитория и распаковать.

В корне проекта:

```bash
python scripts/dev.py
```

На macOS/Linux команда Python может называться `python3`:

```bash
python3 scripts/dev.py
```

Скрипт создаёт виртуальное окружение, устанавливает зафиксированные зависимости, запускает оба сервера и открывает браузер. В Windows можно использовать `py -3 scripts/dev.py`. Для запуска без открытия браузера: `python scripts/dev.py --no-browser`.

**Остановка обоих серверов — `Ctrl+C` в том же терминале.** Изменения сохраняются в `backend/data/serviceflow.db`. Логи: `.local/backend.log` и `.local/frontend.log`. Повторный запуск переиспользует установленные зависимости, если lock-файлы не менялись.

Приложение слушает только локальный компьютер. Порты 3000 и 8000 должны быть свободны. Регистрация и настройка `.env` не нужны. Шрифты поставляются с приложением; после установки зависимостей интерфейсу не нужен внешний CDN.

## Сценарий проверки за 3–5 минут

1. Откроется заказ-наряд **ЗН-1042**, Toyota Camry. Исходная сумма — **18 500 ₽**, дополнительное предложение — **13 400 ₽**. Пока решение не получено, согласованная сумма остаётся **18 500 ₽**.
2. В роли **«Мастер-приёмщик»** нажмите **«Зафиксировать решение»**. Выберите «Отклонить всё», затем согласуйте замену колодок. Необходимые колодки выберутся автоматически. Ремень останется отклонённым.
3. Укажите способ и время согласования, контакт клиента, комментарий. Сохраните. Согласованная сумма станет **27 700 ₽**, срок увеличится на **60 минут**.
4. Нажмите **«Передать в работу»**, переключите роль в верхнем правом углу на **«Механик»**. Можно начать только согласованную работу. Начните и завершите замену колодок.
5. Откройте **«История изменений»**: видны сотрудник, время, комментарий, изменение суммы и снимки данных до/после. В **«Документы»** ремень не попал. Можно распечатать сводку / сохранить PDF через диалог печати браузера или выгрузить JSON.
6. Создайте новое предложение, добавьте работы и запчасти. Проверьте черновик, передачу клиенту, полное согласие и полный отказ.
7. Для проверки склада согласуйте ремень и передайте его в работу. Начало замены недоступно до поступления запчасти. В роли мастера отметьте поступление с комментарием.
8. До начала работ руководитель может отозвать согласование или создать новую редакцию. После начала сервер запрещает переписывать решение. Для новых неисправностей создаётся отдельное предложение.

Тема переключается кнопкой солнца/луны вверху и сохраняется в браузере. Четыре роли — демонстрационный переключатель без авторизации, но ограничения операций проверяет и сервер.

## Что реализовано

- Предложения с несколькими работами и запчастями; количество, цена, трудоёмкость, срок поставки.
- Редактирование только черновиков. Новые редакции со ссылкой на предыдущую и повторным согласованием.
- Решение по каждой позиции: полное / частичное согласие / отказ. Проверка обязательных запчастей.
- Подтверждение: кто связался с клиентом, каким способом, с кем, когда получено решение и когда внесено в систему.
- Стоимость в целых копейках. Итог вычисляется из исходных и согласованных позиций.
- Предварительный пересчёт срока и блокировка работ при отсутствии нужной запчасти.
- Разрешение мастера, начало/завершение механиком, выдача запчастей.
- Отмена до начала работ, комментарии и неизменяемые через API снимки истории.
- Защита от параллельного редактирования через версию и атомарное сравнение в БД.
- Сводка согласованного заказ-наряда, печать и JSON.
- Тесты бизнес-правил, браузерные сценарии, линтеры, CI.

## Структура

```text
backend/
  app/
    api.py          HTTP, зависимости, контекст демо-сотрудника
    schemas.py      входные контракты и валидация
    services.py     операции, права, переходы и транзакционная история
    domain.py       расчёты, снимки и бизнес-ошибки
    models.py       модели хранения
    database.py     соединения и сессии
    seed.py         идемпотентные демонстрационные данные
    main.py         сборка приложения
  tests/            проверки бизнес-инвариантов через API
frontend/
  src/app/          App Router, layout, стили
  src/components/   Chakra UI provider и общие компоненты
  src/features/
    proposals/      предложение, формы редакции и решения
    work-order/     рабочий экран, документы, история
  src/lib/          API-клиент, типы, форматирование
  e2e/              браузерные тесты
scripts/dev.py      переносимый локальный запуск
docs/solution.md    единый проектный документ
compose.yaml       локальное окружение Docker
```

Браузер обращается к `/api` на том же origin. Next.js проксирует запросы в FastAPI. Денежные расчёты, права и переходы контролирует сервер. Детали решений и позиций хранятся снимком агрегата; история — отдельными событиями в той же транзакции. SQLite достаточен для автономного демо. Обоснование и ограничения — в проектном документе.

## Разработка и проверки

Зависимости Python фиксируются в `backend/uv.lock`, npm — в `frontend/package-lock.json`. `requirements.txt` экспортируется из uv-lock для установки без uv и Docker.

Бэкенд, нужен [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
cd backend
uv sync --frozen
uv run pytest -q
uv run ruff check app tests
uv run ruff format --check app tests
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Фронтенд, другой терминал:

```bash
cd frontend
npm ci
npm run dev
```

Проверки фронтенда:

```bash
cd frontend
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные тесты сами поднимают отдельную БД в памяти и серверы на портах **8001 / 3001**. Нужны установленные Python-зависимости и `uv` в PATH. На Linux для Chromium: `npx playwright install --with-deps chromium`. Тесты не изменяют пользовательскую демо-базу. Не запускайте одновременно несколько экземпляров браузерных тестов.

Если загрузка тестового Chromium недоступна, можно использовать уже установленный Chrome: в PowerShell `$env:PLAYWRIGHT_CHANNEL='chrome'`, затем `npm.cmd run test:e2e`; в macOS/Linux `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`. В CI используется Chromium.

`npm run build` выполняйте после остановки обычного dev-сервера или с отдельным `NEXT_DIST_DIR`. Для проверки production без Docker: `npm run build`, затем `npm start`; API должен работать отдельно на 8000.

Конфигурация:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SERVICEFLOW_DATABASE_URL` | `sqlite:///./data/serviceflow.db` | БД, путь относительно рабочей папки backend |
| `SERVICEFLOW_SEED_DEMO` | `true` | Создать демонстрационный заказ при первом запуске |
| `API_INTERNAL_URL` | `http://127.0.0.1:8000` | Адрес FastAPI для Next.js; задавать до запуска dev / production-сборки |
| `NEXT_DIST_DIR` | `.next` | Отдельная папка сборки, используется E2E |

В Docker внутренний адрес API задан при сборке фронтенда как `http://backend:8000`. Публикуются только localhost-порты. В режиме без seed нет интерфейса создания первичного заказ-наряда: это модуль дополнительных согласований.

## Сброс демонстрации и неполадки

- **Локально:** остановите серверы и переименуйте папку `backend/data` в резервную копию (например, `data-backup`). При запуске создастся свежая демо-база. Старую базу можно вернуть, остановив серверы.
- **Docker:** `docker compose down -v` удаляет именно данные этой демонстрации без возможности восстановления. Для сохранения используйте обычный `docker compose down`.
- **Порт занят:** остановите ранее запущенный экземпляр. Лаунчер сообщает, какой порт мешает запуску.
- **API недоступен:** проверьте `http://localhost:8000/api/health` и `.local/backend.log`. На экране есть повторная загрузка.
- **Конфликт версии:** экран загрузит актуальные данные; повторите действие после проверки изменений коллеги.
- **PowerShell блокирует npm.ps1:** используйте `npm.cmd` / `npx.cmd`; менять execution policy не требуется. Лаунчер выбирает `.cmd` автоматически.
- **Docker не подключается к Engine:** запустите Docker Desktop и дождитесь готовности Linux Engine.
- **Новая версия схемы:** в демо нет миграций; для него создайте новую базу с резервной копией старой. Для рабочего проекта нужны Alembic и миграции без потери данных.

## Границы демонстрации

Это законченный учебный срез процесса, а не вся система автосервиса. Нет настоящей авторизации, отправки сообщений, подписи клиента, оплаты, фискализации, складского учёта, календаря постов и подключения к 1С. Отметка «передано» фиксирует ручную передачу, а не доставку внешним сервисом. Сводка согласованного заказа не подменяет акт выполненных работ.

`X-Demo-Actor` позволяет менять роль без проверки личности и предназначен только для локальной проверки. Не публикуйте эту демонстрацию как сервис с реальными клиентскими данными. Подробный план интеграции и спорные случаи описаны в [проектном документе](docs/solution.md).
